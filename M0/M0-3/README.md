
## 如何运行

假设仓库位于 `~/22SmartCar`：

```bash
cd ~/22SmartCar/M0/M0-3
python3 sensor_analyzer.py
```

当前实现支持题目允许的**无参数调用方式**：读取当前工作目录中的 `sensor_data.csv`，把 `cleaned_data.csv` 写到同一目录。输出文件已存在时会覆盖其内容。

输入输出路径以终端当前工作目录为基准。通过脚本绝对路径运行程序，不会自动进入脚本所在目录。可以用 `pwd` 查看工作目录。

使用 VS Code 右上角的“运行 Python 文件”时，可启用 `Python › Terminal: Execute In File Dir`，让该操作从当前脚本所在目录启动。

当前未实现 `--input`、`--output` 参数；题目要求至少支持一种调用方式，本实现采用无参数方式。

## 输入格式与统计口径

输入为 UTF-8 编码的 CSV，必须包含小写的 `time` 和 `value` 表头。例如：

```csv
time,value
0.1,10
0.2,12
0.3,11
```

- `time` 和 `value` 都需要能够转换成有限浮点数，不允许空值、普通文本、`NaN` 或无穷大。
- 至少需要一条数据记录；单条数据或所有值相同时，标准差为 `0`，全部保留。
- 其他列不参与统计。均值和标准差只根据 `value` 列计算。
- 均值和标准差使用**清洗前的全部有效数据**计算，之后进行一次离群值筛选。

均值和总体标准差的公式为：

$$
\mathrm{mean}=\frac{1}{n}\sum_{i=1}^{n}v_i
$$

$$
\mathrm{std}=\sqrt{\frac{1}{n}\sum_{i=1}^{n}(v_i-\mathrm{mean})^2}
$$

本实现以 `n` 为标准差公式的分母。

离群值的判定条件为：

$$
|v_i-\mathrm{mean}|>2\times\mathrm{std}
$$

因此代码保留满足 `abs(v - mean) <= 2 * std` 的记录。恰好等于边界的值保留，偏大和偏小的离群值都会剔除。

## 原始缺陷清单

以下按 8 个问题点整理。行号引用[题目提供的原始脚本](https://github.com/Blake-John/22SmartCar/blob/main/round1/M0/M0-3/sensor_analyzer.py)，包含文件开头的文档注释；删除注释或插入新代码后，本地行号会变化，可通过表中的变量和语句定位。

| 编号 | 原始位置 | 现象 | 原因 | 修复方法 |
| --- | --- | --- | --- | --- |
| 1 | 第 37 行，`row["Value"]` | 读取题目数据时出现 `KeyError: 'Value'`，后面的逻辑无法执行 | CSV 实际表头为小写 `value`，字典的键区分大小写 | 改为 `row["value"]`；捕获缺少必要列时的 `KeyError` |
| 2 | 第 47 行，`total / len(data)` | 空文件或只有表头时发生除零错误 | 没有检查数据数量，空列表的长度为 `0` | 读取后先判断 `if not data`，打印提示并以退出码 `1` 结束 |
| 3 | 第 50—53 行，标准差计算 | 数据有明显波动，算出的标准差却接近或等于 `0` | 直接把偏差相加会正负抵消；公式缺少偏差平方和最后的开方 | 累加 `(v - mean) ** 2`，再计算 `math.sqrt(acc / len(data))` |
| 4 | 第 57 行，`v > mean + 2 * std` | 只剔除偏大的异常值，偏小的异常值被保留 | 判定只检查上界，没有检查负方向的偏差 | 使用偏差绝对值；保留 `abs(v - mean) <= 2 * std` 的数据 |
| 5 | 第 56—58 行，遍历 `data` 时执行 `data.remove(v)` | 连续出现离群值时，部分值可能被跳过 | 删除元素会使后面的元素向前移动，而循环仍继续向后访问 | 遍历原列表，将符合条件的记录追加到新的 `cleaned` 列表 |
| 6 | 第 28 行声明 `cleaned`，第 65 行遍历它输出 | 清洗后条数为 `0`，输出文件可能只有表头 | 原代码修改了 `data`，却从未向 `cleaned` 添加记录 | 筛选时调用 `cleaned.append((t, v))` |
| 7 | 第 61 行，`os.path.join("/", OUTPUT_DIR, OUTPUT_FILE)` | 尝试写入 `/out/cleaned_data.csv`，可能因目录不存在或权限不足失败 | 开头的 `/` 使路径从文件系统根目录开始，也不符合题目默认写入当前目录的要求 | 使用 `output_path = OUTPUT_FILE`，输出到当前工作目录 |
| 8 | 第 65—66 行，`writer.writerow([v])` | 即使 `cleaned` 中有数值，每行也只有一个字段，与 `time,value` 表头不匹配 | 写入时没有保留和输出对应时间 | 使用 `zip(times, data)` 配对并保存 `(t, v)`，写入 `[t, v]` 两个字段 |

排查顺序存在依赖：列名错误最先中断读取；修正读取后，才能分析统计计算；修正输出路径后，才能检查输出内容。标准差错误又会影响离群值判定，因此不能只消除运行报错，还需要核对数值和输出文件。

## 额外的异常处理与文件管理

在上述修复基础上，还补充了以下处理：

| 检查或异常 | 当前处理 |
| --- | --- |
| 输入文件不存在，`FileNotFoundError` | 打印找不到输入文件的提示，退出码 `1` |
| 必要列不存在，`KeyError` | 打印缺少的列名，退出码 `1` |
| 文本、空字符串无法转换成数字，`ValueError` | 打印所在行号及原因，退出码 `1` |
| 某行缺少字段，`float(None)` 产生 `TypeError` | 由数值转换异常处理分支捕获，退出码 `1` |
| 输入含 `NaN` 或无穷大 | `math.isfinite()` 检查失败后主动抛出 `ValueError`，交给已有处理分支 |
| 其他读取或写入错误，`OSError` | 打印文件操作失败原因，退出码 `1` |
| 空文件或没有数据记录 | 在计算均值之前主动退出，退出码 `1` |

读写文件使用 `with open(...)`，离开代码块时自动关闭文件；写入 CSV 时指定 `newline=""` 和 UTF-8 编码。输入文件对象命名为 `input_file`，输出文件对象命名为 `output_file`。

具体的 `FileNotFoundError` 处理放在通用的 `OSError` 处理之前。处理后的错误显示可读提示，不向用户直接输出原始栈回溯。

### 手动测试的复现方法

由于脚本按当前工作目录寻找输入文件，可以在独立的测试目录里放置同名 CSV，再运行上级目录中的脚本。下面以非数字输入为例：

```bash
mkdir -p ~/22SmartCar/M0/M0-3/tests/non_numeric
cd ~/22SmartCar/M0/M0-3/tests/non_numeric
printf 'time,value\n0.1,abc\n' > sensor_data.csv
python3 ../../sensor_analyzer.py
echo $?
```
